# Business Entity Resolution — Team Debug Divas

Solution for the **ML Challenge 2026: Business Entity Resolution** (see [PROBLEM_STATEMENT.md](PROBLEM_STATEMENT.md)).
Given business records from three noisy sources (US, India, and unseen France at test time), find every
Source 2 / Source 3 record that refers to the same business as each Source 1 entity.

**Pipeline:** sparse TF-IDF retrieval (top-50) → learned candidate pruner (~8 candidates per entity)
→ two-stage LightGBM matcher (67 pair features + 9 context features) → one-owner assignment
→ per-entity expected-F0.5 decision.

| Validation (60k held-out entities) | v1 | **v2 (current)** |
|---|---|---|
| Macro F0.5 | 0.9667 | **0.9714** |
| Training entities | 150k | 1M |
| Final candidates per entity (test) | 8.49 | 8.49 |

## Repository layout

| Path | Contents |
|---|---|
| `code/business_entity_resolution/` | runnable pipeline: `src/`, `README.md` (exact run steps), `requirements.txt`, `run_all.sh` |
| `Documentation_template.md` | full methodology write-up (EDA, blocking, features, model comparison, results) |
| `output/matching_results.tsv` | leaderboard submission (test predictions) |
| `utils/validate_submission.py` | organisers' submission validator |
| `make_submission.sh` | validates outputs and builds `<team>_submission.zip` |

Not tracked (too large or regenerated): `dataset/` (download from the challenge portal),
`work/` (intermediate files), `.venv/`, `output/candidate_pairs.tsv` (212 MB, regenerated by
`run_all.sh`), and the submission zip.

## Reproduce

```bash
python3 -m venv .venv && . .venv/bin/activate
pip install -r code/business_entity_resolution/requirements.txt
bash code/business_entity_resolution/run_all.sh "$PWD/dataset" "$PWD/work" "$PWD/output"
python3 utils/validate_submission.py --matching output/matching_results.tsv --candidate output/candidate_pairs.tsv --test-dir dataset/test
```
